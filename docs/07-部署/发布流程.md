# 发布流程

## 1. 版本号约定

| 版本 | 阶段 |
|------|------|
| v0.1.0 ~ v0.4.0 | 第一~四阶段 |
| v0.5.0 | 第五阶段中间成果（实时预测接线 + 预测 API + SHAP） |
| v1.0.0 | 第五阶段完成（LSTM + 数据库迁移 + Docker + 性能优化） |

## 2. 发布前检查清单

- [ ] `pytest` 全量通过（跳过项已说明原因：需 cv2/mediapipe 环境、需 torch）
- [ ] 无 `print` 调试输出，日志统一走 `logging`
- [ ] 无硬编码路径/端口/数据库，配置统一走 `configs/*.yaml`
- [ ] 遵守 PEP8、Type Hint、Docstring；函数 ≤100 行、文件 ≤500 行
- [ ] 未修改既有公开接口与数据库既有字段
- [ ] 文档（README / CHANGELOG / 任务看板 / 部署 / 测试）与代码一致

## 3. 发布步骤

1. 合并功能分支到 `develop`，通过全量测试；
2. 更新 `docs/CHANGELOG.md` 与版本号；
3. 打 tag：`git tag v1.0.0`；
4. 合并 `develop` 到 `master`（禁止直接向 master 提交）；
5. 构建镜像：`docker build -t student-early-warning:v1.0.0 .`；
6. 部署：`docker-compose up -d`。

## 4. 回滚

保留上一版本镜像与数据库备份（`data/`、`models/`），必要时：

```bash
docker-compose down
docker run --rm -p 5000:5000 student-early-warning:<上一版本>
```
