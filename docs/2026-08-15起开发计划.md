# 二、开发原则

延续项目一贯的"框架优先、接口优先、模块解耦、逐步完善"策略，并针对本阶段补充以下原则：

1. 先接线、后优化：优先把已完成的独立模块（RiskPredictor、XGBoost、Feature Engineering）接入运行时链路，再逐步提升精度与性能；
2. 先可部署、再可扩展：先完成单机 Docker 部署与 MySQL 迁移，再引入 InfluxDB、多摄像头等扩展能力；
3. 每个子项完成后立即补测试与文档，保持文档与代码同步；
4. 不破坏既有接口：新增能力通过新接口/新模块接入，不改动已完成模块的公开接口（遵守 AGENTS.md 接口兼容要求）。

# 四、开发内容

## 4.1 实时预测接入在线预警链路

将第四阶段完成的 RiskPredictor / XGBoost / Feature Engineering 接入运行时 Pipeline：

- Pipeline 每产生一个 30 秒滑动窗口特征向量，调用 RiskPredictor 输出风险类别/概率/等级；
- 将预测结果写入数据库（新增 `PredictionLog` 表），并触发在线预警；
- 与现有规则阈值预警并存，形成"规则 + 模型"双通道预警；
- 保持 RiskPredictor 独立模块接口不变，仅新增接线层。

交付：

- `PipelineService` 增加预测阶段（FeatureBuilder → RiskPredictor → PredictionLog/WarningLog）；
- 模型可通过 `ModelRegistry` 统一加载（`models/xgboost/v1`）。

---

## 4.2 Flask API 预测接口

新增 REST 接口，对外提供预测能力：

| 端点 | 说明 |
|------|------|
| `POST /api/predict` | 输入特征向量，返回风险类别/概率/等级 |
| `GET /api/predictions` | 查询历史预测记录 |
| `GET /api/model/info` | 查询当前加载模型版本/特征名/元数据 |

要求：

- 请求/响应结构遵循 `docs/06-开发规范/API规范.md`（当前为空，需一并补齐）；
- 返回字段与 `RiskPredictionResult` 结构一致。

---

## 4.3 SHAP 可解释性

依据 `docs/05-机器学习/SHAP.md` 设计实现：

- 使用 `shap.TreeExplainer` 对 XGBoost 模型生成特征贡献值；
- 输出全局解释（特征重要性排序）与局部解释（单次预测特征贡献）；
- 生成 Summary Plot / Waterfall Plot / Bar Plot；
- 在 Dashboard 中展示"风险原因"（如：疲劳程度高、持续低头）。

交付：

- `src/models/shap/` 模块；
- Dashboard 风险解释面板；
- 预测接口可选返回 SHAP 贡献。

---

## 4.4 LSTM 时序预测

依据 `docs/05-机器学习/LSTM.md` 设计实现：

- 基于 Feature Engineering 输出的连续特征序列构建时间序列样本（seq_len 60）；
- 训练 LSTM（PyTorch），预测未来课堂状态趋势/风险概率；
- 与 XGBoost 形成"当前状态分类 + 未来趋势预测"双层架构；
- 模型保存于 `models/best/lstm_model.pth`，通过 ModelRegistry 统一管理。

交付：

- `src/models/lstm/` 完整实现（训练/推理/保存/加载）；
- 趋势预测接入 Dashboard；
- LSTM 相关 pytest。

---

## 4.5 补齐 MAR / 打哈欠与行为事件持久化

补齐前四阶段遗留的视觉能力缺口：

- 实现 `src/cv/mouth/mouth_mar.py` 真实 MAR 计算（替换占位 `return 0.0`），接入 Fatigue 的 Yawn 分量；
- 运行时将行为事件（blink/head_down/yawn/looking_away/absent）写入 `BehaviorRecord`（`DatabaseService.insert_behavior` 已有，仅缺 Pipeline 调用）；
- 消费 MediaPipe Pose 关键点，用于"身体姿态/离开画面"判断。

交付：

- MAR 计算与打哈欠检测；
- BehaviorRecord 运行时写入；
- Pose 关键点接入行为判断。

---

## 4.6 数据库迁移（MySQL + InfluxDB）

- 在保留 SQLite（开发/演示）的基础上，新增 MySQL 支持（`DatabaseService` 抽象出统一接口）；
- 高频时序数据（FrameRecord/StateRecord）迁入 InfluxDB（可配置开关）；
- 新增 `PredictionLog` 表（见 `docs/03-数据库/数据库设计.md` 12 节预留扩展）；
- 提供数据迁移脚本（SQLite → MySQL）。

要求：

- 不修改现有表字段（遵守 AGENTS.md）；
- 通过配置 `configs/database.yaml` 切换后端，默认仍为 SQLite。

---
