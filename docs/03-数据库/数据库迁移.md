# 数据库迁移（SQLite → MySQL + InfluxDB 预留）

## 1. 后端切换

系统默认使用 SQLite，通过 `configs/database.yaml` 的 `database.backend` 切换后端：

| backend | 说明 | 依赖 |
|---------|------|------|
| sqlite | 默认，单机文件数据库 | 无 |
| mysql | 关系型数据库（生产/多用户） | pymysql |

切换示例：

```yaml
database:
  backend: "mysql"
mysql:
  host: "127.0.0.1"
  port: 3306
  user: "root"
  password: ""
  database: "early_warning"
  charset: "utf8mb4"
```

`DatabaseService` 通过 `src/database/backends.py` 中的后端抽象统一访问，
上层 `insert_*` / `query_*` 接口与 SQL 语句不变，仅底层占位符（`?` / `%s`）与 DDL 按方言适配。

## 2. 表结构

MySQL 表字段名与 SQLite 完全一致（含第 1 步新增的 `PredictionLog`），
仅类型与约束按 MySQL 方言调整（如 `AUTOINCREMENT` → `AUTO_INCREMENT`、`TEXT` → `VARCHAR`/`TEXT`）。

不修改任何既有字段名，保证上层代码与接口兼容。

## 3. 数据迁移脚本

`scripts/migrate_sqlite_to_mysql.py` 将 SQLite 数据迁移至 MySQL：

```bash
python scripts/migrate_sqlite_to_mysql.py [--source data/early_warning.db]
```

迁移前需在 MySQL 中创建目标数据库：

```sql
CREATE DATABASE early_warning CHARACTER SET utf8mb4;
```

脚本按「无外键依赖 → 外键依赖」顺序迁移 8 张表，并保留主键 id 以维持外键关系。

## 4. InfluxDB 预留

高频时序数据（`FrameRecord` / `StateRecord`）预留 InfluxDB 接入：

```yaml
influxdb:
  enabled: false      # 默认关闭
  url: "http://localhost:8086"
  token: ""
  org: ""
  bucket: "early_warning"
```

启用后 `DatabaseService` 在写入关系库的同时，将帧/状态数据异步写入 InfluxDB
（`src/database/timeseries.py`，需安装 `influxdb-client`）。
写入失败仅记录日志，不影响主流程。
