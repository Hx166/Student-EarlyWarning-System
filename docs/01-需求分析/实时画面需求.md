>

>
> 登记日期：2026-10-31
>
> 来源：用户功能建议，经规划侧确认范围

---

# 1. 现状与问题

实时看板 `/` 已有指标、疲劳分析、规则预警、趋势图与 Engagement 模型等级，但“实时画面”区域仍是占位。用户无法确认摄像头是否采集成功、系统分析的是哪张人脸、指标是否对应同一画面，也无法判断无人脸、光线异常或摄像头断开的原因。

V1 验收不以此项为阻塞；列为 V1.1 的 P1 需求。

---

# 2. 目标

1. 摄像头正常时，看板显示连续画面；
2. 摄像头未就绪、短暂无帧、断开、API-only 时有明确状态；
3. 画面与指标来自同一条采集链路，不重复打开摄像头；
4. 画面只本地预览，不入库、不录制、不上传；
5. 页面关闭或网络断开后释放视频流资源，不影响主流水线。

---

# 3. 范围（MVP）

## 3.1 画面

- 浏览器原生 MJPEG，`<img>` 直接显示，不引入前端框架；
- 默认 640×480，可配置；展示 10–15 FPS，避免与模型推理争抢 CPU；
- 仅本机演示使用。

## 3.2 状态

| 状态 | 页面表现 |
|---|---|
| 初始化中 | “正在连接摄像头…” |
| 正常 | 显示实时画面 |
| 短暂无帧 | 保留最近画面，显示“画面等待中” |
| 摄像头不可用 | “摄像头未连接，可使用视频回放”，附 `/playback` 链接 |
| 后端断开 | “服务连接中断” |
| API-only | “当前为回放模式，无实时摄像头” |

## 3.3 辅助信息

画面区域内显示分辨率、采集 FPS、最近更新时间、模型版本。

## 3.4 不做

- 人脸框与关键点叠加（列为可选增强，不进 MVP）；
- 画面截图、录制、上传；
- 访问控制与账号体系；
- 为网页单独打开第二个摄像头实例。

---

# 4. 与现有模块的关系

```text
Camera
  → Pipeline 主循环（唯一采集者）
  → 最新帧共享缓冲（JPEG）
  → GET /api/camera/stream（MJPEG）
  → 实时看板
  → 同一帧继续进入 EAR / PERCLOS / 头姿 / 疲劳 / 参与度 / Engagement 模型
```

约束：

- 主流水线是唯一摄像头持有者，网页只读共享缓冲；
- 不修改 Engagement 模型、特征定义、风险语义；
- 不把帧写入 SQLite；
- 页面断开后停止生成帧，主程序退出时正常释放摄像头。

---

# 5. 接口

```http
GET /api/camera/stream
Content-Type: multipart/x-mixed-replace; boundary=frame
```

返回 JPEG 帧流；页面用 `<img src="/api/camera/stream">`。

```http
GET /api/camera/status
```

```json
{
  "code": 0,
  "data": {
    "state": "live",
    "width": 640,
    "height": 480,
    "fps": 15.0,
    "updated_at": "2026-10-31T12:00:00"
  },
  "message": "ok"
}
```

`state` 取值：`starting`、`live`、`waiting`、`unavailable`、`api_only`。

无摄像头或 API-only 时：`stream` 返回 503，`status` 返回 `unavailable` / `api_only`，页面显示提示，不报错。

# 6. 规划侧决定

| 问题 | 决定 |
|---|---|
| MVP 是否叠加人脸框 | 不叠加；只做画面。人脸框列为 V1.2 可选增强 |
| 分辨率与帧率 | 640×480、10–15 FPS；写入配置，可调 |
| 摄像头不可用是否自动跳转回放 | 不自动跳转；显示提示与 `/playback` 链接，避免打断演示 |
| 是否要截图按钮 | 不要；避免保存与隐私问题 |
| 是否要访问控制 | MVP 不做账号；服务默认仅本机监听，局域网演示需手动改 `server.host` |

---

# 7. 验收标准

- [ ] `python -m src.main` 启动后 3 秒内看板出现画面
- [ ] 画面、指标、模型等级来自同一采集链路
- [ ] 拔出摄像头：显示断开提示，不白屏、不无限报错
- [ ] 重连后恢复画面，或刷新页面可恢复
- [ ] `--api-only`：显示回放模式提示，`/playback`、`/model` 不受影响
- [ ] 页面关闭后视频流请求结束，主程序可正常退出并释放摄像头
- [ ] `/api/state`、`/api/predict`、`/api/prediction/latest` 行为不变
- [ ] 不新增大型依赖、不改数据库、不重训模型
